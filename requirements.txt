# Runtime dependencies for the Vercel Python Functions under /api. Separate
# from ml/requirements.txt, which pins CUDA training-time packages (cupy,
# duckdb) that don't belong in a serverless inference bundle.
#
# xgboost-cpu is the CPU-only PyPI distribution (same `xgboost` import) —
# the regular `xgboost` wheel pulls in nvidia-nccl-cu13 as a hard dependency
# (~290 MB) purely for optional multi-GPU support this serverless function
# never uses.
#
# Pinned below 3.1: xgboost-cpu 3.1+ (and its numpy/scipy resolved by
# default) only publish `manylinux_2_28` wheels, no `manylinux2014` variant.
# Vercel's build-time dependency resolution rejects manylinux_2_28-only
# wheels as "incompatible" and falls back to building from source, which
# blew the bundle size limit even after removing nvidia. 3.0.5 is the newest
# xgboost-cpu release with a manylinux2014 wheel, same major (3.x) version
# line as the promoted models (trained with xgboost 3.4.1) — verify the
# UBJSON models still load cleanly under 3.0.5 on first real deploy; roll
# forward to a newer manylinux_2_28-only version if Vercel's runtime is
# confirmed to support it (this pin exists for the *build step's* wheel
# selection, not necessarily the runtime container itself).
xgboost-cpu>=3.0.5,<3.1
numpy>=1.26,<1.27
scipy>=1.13,<1.14
